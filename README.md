# 星座問卷工作坊：金牛座真的愛家嗎？

中興大學 生物產業管理研究所（生管學程）1151 學期「量化研究法（上）」第 6 週課堂網站，授課教師：王思永。

全班用手機掃 QR、免登入、輸入一個 ID 就進場（不分組），走完「構面表 → 出題 → 健檢互評 → 定稿 → 兩輪作答 → 立刻開獎 → 下載 Excel」整條鏈。出題與互評記 ID，問卷作答匿名（只記星座）。老師用控制台推進階段，學生手機畫面即時跟著切換；投影畫面即時顯示題目牆、票數與開獎圖。

線上網址：https://halcyone1234-ux.github.io/zodiac-survey/

## 畫面

| `/#dims` | 學生 | 構面表：概念 → 構面 → 指標（全班共用一張，標記提出者） |
| `/#propose` | 學生 | 出題：題目、題型（比率／李克特／單選）、構面、用了哪一招 |
| `/#vote` | 學生 | 健檢互評：列入／不列入，七宗罪 ×7、四把刀 ×4，講評 |

| `/#results` | 學生 | 開獎（老師開放後）：三件事＋B1–B3 分布＋下載 Excel |

| `/#admin` | 老師 | 控制台（PIN）：切階段、門檻、定稿與題序、輪次、開放結果、概念清單、Excel、重置 |

網址加 `?c=代碼`（例如 `?c=1152-w06`）可開一個全新的班級資料，下學期重用。

## 課堂操作 SOP（對照 W06 簡報）

1. 課前：控制台 → 「清空資料」。投影畫面開 `/#board`，學生掃 QR 進場（輸入 ID、選星座）。
2. 構面表（簡報 p.9–11）：控制台切「構面表」。全班一起在「愛家」「浪漫」下填構面與指標，投影牆即時顯示。想自創傳說可在控制台加概念。
3. 出題（p.12–19）：切「出題」。每人至少 1 題、全班 8–12 題，比率題與李克特題都要有；每題必選構面（追問測試）。
4. 健檢互評（p.14、20）：切「健檢互評」。學生投票與開刀；學生看不到票數，投影看得到票數與記名講評。
5. 定稿（p.15–16）：切「定稿中」（學生看等待畫面）。控制台「套用投票建議」、手動勾選與調整題序、決定 B1–B3 放開頭或最後，按「定稿並開始第一輪作答」。
6. 作答（p.21）：第一輪自評。收齊後在控制台選目標星座（金牛）按「第二輪：代答此星座」；可再換雙魚跑一次。
7. 開獎（p.22–24、30）：切「進入開獎」，投影顯示三件事；按「開放學生看結果與下載」讓學生看圖與下載 Excel。

## Excel 內容

`題目`（含出題者、投票結果與開刀標籤）、`作答_寬表`（一列一份作答，Q1…Qn、B1–B3）、`作答_長表`、`投票紀錄`（記 ID）、`構面表`、`摘要`（各題依元素平均；自評 vs 代答）、`進場名單`。作答資料匿名，只含星座與元素。

## 安裝（第一次）

1. 到 https://console.firebase.google.com 建立專案（例如 `zodiac-survey`），不需要 Google Analytics。
2. 左側「建構 → Realtime Database → 建立資料庫」，位置選 `asia-southeast1`（新加坡），以「鎖定模式」開始。
3. 「規則」分頁：把本 repo 的 `database.rules.json` 內容整份貼上，發布。
4. 「專案設定 → 一般 → 你的應用程式 → 新增應用程式 → 網頁（</>）」，取得 `firebaseConfig`。
5. 把 `apiKey`、`authDomain`、`databaseURL`、`projectId`、`appId` 填進 `firebase-config.js`；順便改 `adminPin`。
6. push 到 GitHub，Pages 以 main 分支根目錄發布。

`firebase-config.js` 的 apiKey 還是 `YOUR_…` 時，網站會自動改用「本機測試模式」：資料只存在這台瀏覽器的 localStorage，同一台電腦的多個分頁會互相同步，方便試跑流程。

## 技術

- 純靜態：`index.html`、`style.css`、`app.js`（路由與畫面）、`data.js`（Firebase／mock 資料層）、`results.js`（統計、圖表、Excel），無建置步驟。
- CDN：Firebase JS SDK 10.12（compat）、Chart.js 4.4.1、SheetJS 0.18.5、qrcodejs 1.0.0。
- 身分：每支手機自動產生匿名碼存在 localStorage，進場時自行輸入 ID（同一 ID 不能重複）；每題一票、每輪一份作答，可覆寫自己的。構面、題目、投票帶 ID，作答只帶星座。
- 安全：Realtime Database 規則開放讀取、限制寫入欄位；作答只能由同一匿名碼覆寫。控制台 PIN 只在前端把關，適合課堂規模；若要硬化，可改用 Firebase Anonymous Auth 加老師帳號，並在規則中以 `auth.uid` 限制 `session`、`survey` 的寫入。
- Firebase 免費方案（Spark）的 Realtime Database 同時連線 100、儲存 1 GB，一班 14 人綽綽有餘。
